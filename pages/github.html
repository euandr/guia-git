―― PRIMEIROS PASSOS

Ambiente remoto e segurança

Prepare sua conta, conheça a interface e configure formas seguras de acesso.

01

Criando sua conta

Acesse o GitHub e explore a interface principal.

  1. Acesse github.com e crie uma conta.
  2. Conheça o Dashboard, onde aparecem seus projetos e atualizações.
  3. Explore Repositories, onde ficam os arquivos e o histórico de commits.
02

Autenticação segura

O GitHub utiliza métodos de autenticação para proteger o acesso aos repositórios.

  • Token de Acesso Pessoal (PAT): token utilizado para autenticação em operações compatíveis.
  • Chave SSH: par de chaves criptográficas que permite autenticação pelo terminal.
03

Gerenciamento de colaboradores

Adicione integrantes ao repositório para que a equipe possa trabalhar em conjunto.

  1. Abra o repositório no GitHub.
  2. Entre em Settings → Collaborators.
  3. Clique em Add people.
  4. Envie o convite para os colegas.

―― LOCAL ⇆ NUVEM

Sincronização de código

Conecte o computador de cada integrante ao repositório remoto e mantenha o projeto atualizado.

01

Clonando um repositório

Se o projeto já existe no GitHub, faça uma cópia completa para o computador.

git clone https://github.com/usuario/nome-do-projeto.git
02

Vinculando ao GitHub

Conecte uma pasta local a um repositório remoto existente.

git remote add origin https://github.com/usuario/nome-do-projeto.git
03

Enviando alterações

Depois do commit, envie as alterações locais para o GitHub.

git push origin main
04

Atualizando o projeto

Baixe as alterações mais recentes antes de começar a trabalhar.

git pull origin main
Dica de ouro

Use git pull no início do trabalho para evitar desenvolver sobre uma versão desatualizada do projeto.

―― COLABORAÇÃO

Fluxo de trabalho em equipe

O GitHub Flow organiza alterações por branches e permite revisar o código antes da integração.

01

Branch

Crie uma branch para cada tarefa, em vez de alterar diretamente a main.

git checkout -b feature-login
→
02

Pull Request

Envie sua branch para o GitHub e abra um PR para propor a integração.

→
03

Code Review

A equipe pode comentar, solicitar ajustes e aprovar as alterações.

→
04

Merge

Depois da revisão, a alteração pode ser integrada à versão principal.

―― QUANDO HÁ CONFLITO

Resolução de conflitos de merge

Quando branches alteram as mesmas linhas de um arquivo, o GitHub sinaliza o conflito para que a equipe escolha como resolver a diferença.

  1. Identifique os arquivos em conflito.
  2. Escolha a versão adequada usando o GitHub ou seu editor.
  3. Faça o commit da resolução e finalize o merge do PR.

―― ORGANIZAÇÃO

Gerenciamento de projetos acadêmicos

Use os recursos do GitHub para organizar tarefas, prazos e responsabilidades do grupo.

01

GitHub Issues

Transforme tarefas e problemas em itens acompanháveis dentro do repositório.

  • Crie uma Issue para cada tarefa.
  • Atribua responsáveis.
  • Use labels como bug, documentation e enhancement.
02
